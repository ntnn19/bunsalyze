# Bunsalyze

For questions/issues/feedback please use GitHub Issues or contact Benjamin Fry (bfry@g.harvard.edu)
___


### Description

Python module for counting buried polar atoms with unsatisfied hydrogen bonds. 
Used for ranking and selection of designed Protein-Ligand interfaces generated by LASErMPNN / NISE.
The lower the number of buried unsatisfied polar atoms, the better the design. 
We typically score protein-ligand interfaces by upweighting the ligand BUN contributions by 2x relative to protein BUNs contributions ('buns_score') and tiebreak by ('buns_capacity_score')

### Installation

```bash
uv venv --python 3.11
source .venv/bin/activate
uv pip install .
```


### Usage

With the venv / conda environment that bunsalyze has been pip installed into you can run:

```bash
bunsalyze ./path/to/pdb_file.pdb 'smiles_string_for_ligand'

# Example using the bundled epic_1.pdb structure:
bunsalyze example_pdbs/epic_1.pdb 'CC[C@]1(O)C2=C(C(N3CC4=C5[C@@H]([NH3+])CCC6=C5C(N=C4C3=C2)=CC(F)=C6C)=O)COC1=O'
```

Alternatively, install with `pip install .` and run with `bunsalyze ...`.

#### Multiple ligands

Complexes containing more than one ligand residue are supported. The `smiles` argument
maps onto ligand residues in three ways:

- **One SMILES** (string or single CLI argument): broadcast to every ligand residue —
  e.g. multiple copies of the same ligand bound across a homomer.
- **One SMILES per ligand residue** (CLI: space-separated; API: list): matched to ligand
  residues sorted by (chain, resnum, icode) — use this for multiple *different* ligands.
- **A mapping** (API: dict; CLI: `--smiles_map '{...}'`) locating each ligand residue by:
  - **resname** — `{'FAD': '...'}` covers every FAD copy (but cannot distinguish two
    different ligands sharing a resname; AlphaFold3 names every SMILES-specified ligand
    `LIG`, so prefer chain keys for AF3 outputs);
  - **chain ID** — `{'B': '...', 'C': '...'}` covers the ligand residue in that chain
    (rejected if a chain contains more than one ligand residue);
  - **chain:resnum** — `{'B:501': '...'}` covers exactly one residue.
  The mapping is validated: every key must match a ligand residue, no residue may be
  covered by more than one key, and keys that are simultaneously a chain ID and a resname
  are rejected as ambiguous. Residues left uncovered by the map are auto-resolved (see
  below). This is the fail-proof option for multiple different ligands.

```bash
# two copies of the same ligand (chains L and M both resname LIG):
bunsalyze complex.pdb 'CC(=O)NC1=CC=C(C=C1)O'

# two different ligands, matched in (chain, resnum) order:
bunsalyze complex.pdb 'CC(=O)NC1=CC=C(C=C1)O' 'CN1C=NC2=C1C(=O)N(C(=O)N2C)C'

# two different ligands, keyed explicitly by chain ID (fail-proof):
bunsalyze complex.pdb --smiles_map '{"B": "CC(=O)NC1=CC=C(C=C1)O", "C": "CN1C=NC2=C1C(=O)N(C(=O)N2C)C"}'
```

Global scores aggregate over every ligand residue (`buns_score` remains
`2 * len(ligand_buns) + len(protein_buns)` with `ligand_buns` spanning all copies; the
output adds an `n_ligand_residues` field). **Per-ligand scores** are reported under
`per_ligand`: one entry per ligand residue with its `residue_id`, its own `ligand_buns`,
`n_ligand_buns`, `n_buried_ligand_polar_atoms`, `ligand_buried_binary_unsat`,
`ligand_buried_per_atom_capacity`, and a per-site `shell_buns` block (shells expanded from
that ligand alone — `shell_buns.cumulative_buns_score[1]` is the per-site equivalent of the
recommended ranking score). Burial and the H-bond graph are still solved on the whole
complex, so inter-ligand H-bonds and mutual burial are fully accounted; only the
attribution is per residue. A protein BUN within shell range of two ligands is attributed
to both sites, and protein BUNs outside every ligand's shells appear only in the global
scores — so per-site scores need not sum to the global `buns_score`. Because bare atom names collide across copies,
the per-atom ligand annotation dicts/lists (`ligand_atoms_sasa`, `ligand_atoms_in_hull`,
`ligand_atoms_buried_sasa`, `ligand_atoms_considered_buried`, `ligand_per_atom_capacity`,
`ligand_buried_per_atom_capacity`) use `name:chain:resname:resnum:icode` keys whenever more
than one ligand residue is present (single-ligand output is unchanged). H-bonds between
*different* ligand residues count as intermolecular; `--ignore_ligand_intramolecular_hbonds`
only ignores H-bonds within the same ligand residue.

#### Automatic ligand chemistry (SMILES optional)

The SMILES argument is **optional**. Every ligand residue without a user-supplied SMILES
is auto-resolved, per residue, by the first source that matches its heavy-atom graph:

1. **explicit user SMILES** (positional / `--smiles_map`) — authoritative; a SMILES that
   does not match the residue's coordinates is a hard error (`chemistry_source: "user"`).
2. **the input mmCIF's own chemistry** — the `_chem_comp_bond`/`_chem_comp_atom` tables
   that RCSB entries carry for CCD ligands (`chemistry_source: "mmcif_bond_table"`), or
   `_chem_comp.pdbx_smiles`, which AlphaFold 3 writes for its ligands and which preserves
   the SMILES AF3 was given, protonation state included
   (`chemistry_source: "mmcif_pdbx_smiles"`).
3. **CCD lookup by resname** via the RCSB chemcomp API
   (`chemistry_source: "ccd:<RESNAME>"`; skip with `--no_ccd_lookup` for offline use).
4. **geometry perception** from the coordinates alone
   (`chemistry_source: "geometry_perception"`) — least reliable (geometry-dependent, blind
   to tautomers/protonation); a loud stderr warning is emitted for every such ligand.

Auto-derived sources (2–4) are best-effort: if a source's template does not match the
residue, resolution falls through to the next one. A residue no source can describe is
**excluded from scoring** and recorded in the top-level `excluded_ligands` list (with a
stderr warning); the run only fails if *no* ligand residue is scoring-compatible. Every
`per_ligand` entry records `chemistry_source` and `chemistry_smiles` (the canonical SMILES
of the template actually used), so an implicit choice is always an auditable choice.

mmCIF inputs (`.cif`/`.mmcif`/`.bcif`) are parsed directly; SASA calculation is handled
through an internal PDB rendering since freesasa only reads PDB. The default ligand
selection is `not protein and not nucleic and not water and not ion`, so multi-ligand
structures are scored without any selection flags (waters/ions are never scored as
ligands); override with `--override_ligand_selection_string`.

```bash
# RCSB entry: biotin chemistry comes from the entry's own bond table
bunsalyze 1stp.cif

# AF3 model: ligand chemistry comes from AF3's _chem_comp.pdbx_smiles records
bunsalyze fold_model.cif

# offline: never query the CCD
bunsalyze complex.pdb --no_ccd_lookup
```

The output always includes a `shell_buns` key with the following structure:

```python
'shell_buns': {
    'shell_dist': 5.0,          # contact distance used
    'n_shells': 3,              # number of shells computed
    'cumulative_buns_score':    [int, ...],   # buns_score restricted to ligand + shells 1..k
    'cumulative_capacity_score': [float, ...], # buns_capacity_score restricted to ligand + shells 1..k
    'per_shell_protein_buns_count': [int, ...], # protein BUNs first reached at each shell depth
}
```

`cumulative_buns_score[1]` (ligand + first two shells) is recommended for ranking protein–ligand
designs as it focuses on the binding pocket and reduces noise from surface Glu/Asp/Arg/Lys residues
that vary across designs but are not involved in ligand contacts.
